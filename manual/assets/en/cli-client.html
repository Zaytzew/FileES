One-shot CLI client

Implemented filees-client performs one operation and exits. It is a separate Linux/OpenBSD binary for a user or a user's cron job. It does not run the desktop daemon, and it is not part of the server bundle. The 0.1.0 archive includes the executable, README and filees-client(1) in share/man/man1/. Run filees-client version to see the version and source revision.

The CLI uses an activated FileES identity and a pinned SSH host key. Store the identity, configuration, journal and operation state outside published directories. Use a dedicated operating-system account for strict local separation. The CLI has no shelves, drawers, public shares or Time Machine.

Configuration and activation

The new CLI's autoconfig lists repositories from an existing activation. Select an exact repository name and an explicit source directory; the key, port and UUID come from activation. Use --state-root for an older servers directory, --profile for an existing profile, or --activation for one activated server directory. No new OTP is needed. Select --server NAME when several servers are activated.

filees-client autoconfig
filees-client autoconfig --repo 'Faktury 2026' --source /home/user/published/2026 --name faktury-2026
filees-client publish faktury-2026

The source is never widened to its parent: the example uploads the months of 2026 directly. Private profiles and journals live in $XDG_CONFIG_HOME/filees-cli or ~/.config/filees-cli; use the same custom --config-root for both commands, outside the source. Repeating the same configuration is idempotent; another source or repository needs another name. Tools are discovered on PATH and saved as absolute paths. The INI configuration below remains supported for the older commands.

Activation uses activate-begin, activate-finish (one OTP from standard input) and activate-resume. Copy an activated profile only through a deliberately authorised process. For sync, an INI file lists exact tool paths, identity, known-hosts, private log_dir and named [wc "id"] sections. A --wc argument selects an ID, never a free-form path or URL. Optional only=!id restricts which configured copies may run. The journal is private, rotates after 5 MiB, and must be writable before sync starts.

[tools]
svn=/usr/local/bin/svn
svnmucc=/usr/local/bin/svnmucc
ssh=/usr/bin/ssh
log_dir=/var/log/filees-client
[realm]
identity=/home/user/.filees/identity
known_hosts=/home/user/.filees/known_hosts
host=server.example
port=22
only=!invoices
[wc "invoices"]
path=/home/user/published
url=svn+ssh://_filees-data@server.example/REPO_UUID

Two sync modes

checkout --config … --wc invoices creates a normal SVN working copy. sync --config … --wc invoices then updates it, adds new files, propagates local deletions and commits; conflicts stop publication for manual resolution.

sync --config … --wc invoices -nwc uses the configured path as a plain directory without .svn. It creates missing directories, adds new files and updates changed files through one svnmucc commit. Local deletions are not sent. A path deleted in the repository is skipped by default; -restore-set explicitly permits restoration when that path still exists locally. -reverse-reconcile-set instead makes the local directory match one accessible repository revision, including removal of local extras, without a commit. These two flags are exclusive and require -nwc. The reverse apply phase is not atomic, so rerun after interruption.

These are behaviours of this program, not reduced server grants. A normal desktop activation retains its granted permissions when its key is used by another client. For -nwc, the configured URL must be the repository root; symbolic links and non-regular source files are refused.

Producer and cron

Run the CLI after the publication producer exits successfully. Keep the && chain so a failed producer cannot start FileES. A user crontab may call this once per scheduled run; no additional daemon is needed.

ksefuck && /usr/local/bin/filees-client publish faktury-2026 --message ksefuck

Configure the profile as the cron user. publish refreshes server permissions and refuses offline, revoked access or changed bindings. It adds/updates files in one atomic commit, without propagating local deletions or restoring remotely deleted files. Progress shows stages and counts. The CLI supplies SVN's descriptor soft limit but refuses before commit when the hard limit is insufficient; it never splits a publication. These commands do not install cron. The signed r2016 package has neither autoconfig/publish nor install/update; a new release is required.

Use paths and a schedule appropriate to the deployment. An unchanged rerun creates no commit. A producer failure stops the chain; keep && rather than calling the client unconditionally.

Dump/load and Whale

dump-load --profile PROFILE --dump DUMP --name NAME --target NEW_WC --state PRIVATE_STATE creates a new repository and new working copy. The activation needs repository-creation permission. After uncertain completion, repeat the same arguments and private state directory; the saved operation ID resumes the same import. It never overwrites an existing target.

whale-put publishes a large file. For downloads, whale-get-quote reports the size and operation ID, then whale-get-confirm --id ID explicitly starts transfer. whale-status, whale-retry and whale-resume use the same private state directory.

Interruptions and retries

Extract the archive for your platform and make SVN and SSH available at the configured paths. Read the manual with man -M /path/to/package/share/man filees-client. Commands return 0 on success, 1 on an operation error and 2 for invalid arguments. Use absolute executable paths in cron.

A successful Whale download includes a verified file and confirmation that the server released its download cache and space reservation. The file may already be on disk while the operation is still waiting for confirmation. Inspect whale-status --id ID; use whale-retry --id ID after a failure or whale-resume --id ID after a process interruption, keeping the same profile and state directory. The client checks the existing file and retries release without downloading it again.

Resolve ordinary working-copy conflicts in SVN before repeating sync. After interrupted reverse reconciliation, rerun the same command; applying the entire local tree is not atomic.
