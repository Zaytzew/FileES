NAME

filees-mobile-v1 — FileES mobile protocol entry

SYNOPSIS

filees-mobile-v1

DESCRIPTION

filees-mobile-v1 is the set-id entry for _filees-mobile. The installed image is _filees-state: _filees-access mode 4550, the same class as filees-client-entry(8).

The mobile client is paired from an already activated desktop. It inherits that desktop's repository list once. The phone may read a granted share and write only under mobile-uploads/. A new path is unique-append.

The two write verbs differ on what happens when a path is already taken, and the difference is deliberate. UPLOAD_OBJECT never overwrites and never renames: identical content is dropped as a duplicate (NAME_TAKEN_SAME), and different content is parked for the user to decide (NAME_TAKEN_DIFF). UPLOAD_TREE ingests a marked zip as one commit, skips entries whose content already matches and overwrites the rest as a new revision; an unmarked zip is rejected as a whole. So a re-upload of one changed file does not replace it, while the same file inside an ingested folder does.

An UPLOAD_OBJECT answers with exactly one outcome:

COMMITTED
the object was published
NAME_TAKEN_SAME
the path exists with identical content; dropped as a duplicate
NAME_TAKEN_DIFF
the path exists with different content; parked for the user
DESTINATION_GONE
a file sits where the parent directory should be, or the parent is absent outside mobile-uploads/
ACCESS_REVOKED
the installation no longer holds rw
REPO_INACTIVE
reserved, not implemented yet: repository state does not reach the append worker, so an inactive repository is indistinguishable from an active one
POLICY_REJECTED
reserved, not implemented yet: the mobile policy check named by the protocol has no implementation in the worker

The two reserved outcomes are part of the wire contract and a client may receive them from a future server; no current code path produces either.

Missing parent directories are created only under mobile-uploads/, which is the phone's own album tree. Everywhere else the destination directory must already exist.

The mobile projection does not receive editing_policy.

sshd(8) uses the shared authorized_keys file. The per-key command= line selects this image. There is no ForceCommand on the _filees-mobile match block.

TEMPORARY STORAGE

The optional mobile.temp_root in /etc/filees/server.json selects a dedicated temporary directory. It must exist, be private (mode 0700), and be writable by _filees-state. Symbolic links are rejected. The worker sets its process TMPDIR before applying the sandbox or executing SVN. Spool, ZIP extraction, transient working copies and SVN children use the same directory; the sandbox allows that root instead of the default temporary location. An invalid explicit setting fails without a fallback.

An omitted setting preserves the legacy process temporary directory. The bundle example uses /var/filees-mobile/tmp; choose a sufficiently large filesystem, allowing for concurrent uploads and multiple temporary copies of each file. The capacity monitor includes the configured directory. Upgrade the server binary before adding the field to an old configuration.
