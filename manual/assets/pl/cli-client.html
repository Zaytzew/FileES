Jednorazowy klient CLI

Zaimplementowane filees-client wykonuje jedną operację i kończy pracę. To osobne binarium dla Linux/OpenBSD, uruchamiane przez użytkownika albo jego cron. Nie wymaga demona desktopowego i nie wchodzi do paczki serwera. Archiwum wersji 0.1.0 zawiera program, README i filees-client(1) w share/man/man1/. Polecenie filees-client version pokazuje wersję i rewizję źródeł.

Klient używa aktywowanej tożsamości FileES i przypiętego klucza hosta SSH. Tożsamość, konfigurację, dziennik i stan operacji trzymaj poza folderami publikowanymi. Dla ścisłej izolacji lokalnej użyj odrębnego konta systemowego. Program nie obsługuje półek, szuflad, udziałów publicznych ani Maszyny czasu.

Konfiguracja i aktywacja

W nowym CLI autoconfig pobiera listę repozytoriów istniejącej aktywacji. Wybierz dokładną nazwę i jawny folder źródłowy; klucz, port i UUID pochodzą z aktywacji. Starszy katalog serwerów wskaż przez --state-root, a istniejący profil przez --profile lub katalog jednej aktywacji przez --activation. Nowy OTP nie jest potrzebny. Przy wielu aktywacjach wybierz --server NAZWA.

filees-client autoconfig
filees-client autoconfig --repo 'Faktury 2026' --source /home/user/published/2026 --name faktury-2026
filees-client publish faktury-2026

Źródło nie jest poszerzane do rodzica: przykład wysyła bezpośrednio miesiące roku 2026. Prywatny profil i dziennik są w $XDG_CONFIG_HOME/filees-cli albo ~/.config/filees-cli; własny --config-root podaj w obu komendach i trzymaj poza źródłem. Powtórka tej samej konfiguracji jest idempotentna; inne źródło lub repo wymaga nowej nazwy. Narzędzia są wykrywane na PATH i zapisywane jako absolutne ścieżki. Poniższy INI pozostaje obsługiwanym sposobem konfiguracji starszych poleceń.

Aktywacja przebiega przez activate-begin, activate-finish (jedno OTP ze standardowego wejścia) i activate-resume. Przenoszenie profilu aktywacji wymaga świadomie uprawnionego procesu. Do synchronizacji plik INI wskazuje dokładne ścieżki narzędzi, tożsamość, known_hosts, prywatny log_dir i nazwane sekcje [wc "id"]. Parametr --wc wybiera identyfikator, nigdy dowolną ścieżkę ani URL. Opcjonalne only=!id ogranicza dozwolone wpisy. Dziennik jest prywatny, rotuje po 5 MiB i musi dać się zapisać przed rozpoczęciem synchronizacji.

[tools]
svn=/usr/local/bin/svn
svnmucc=/usr/local/bin/svnmucc
ssh=/usr/bin/ssh
log_dir=/var/log/filees-client
[realm]
identity=/home/user/.filees/identity
known_hosts=/home/user/.filees/known_hosts
host=server.example
port=22
only=!invoices
[wc "invoices"]
path=/home/user/published
url=svn+ssh://_filees-data@server.example/UUID_REPO

Dwa tryby synchronizacji

checkout --config … --wc invoices zakłada zwykłą kopię roboczą SVN. Późniejsze sync --config … --wc invoices aktualizuje ją, dodaje nowe pliki, przenosi lokalne usunięcia i commituje; konflikt zatrzymuje publikację do ręcznego rozstrzygnięcia.

sync --config … --wc invoices -nwc traktuje wskazany katalog jako zwykły folder bez .svn. Tworzy potrzebne katalogi, dodaje nowe pliki i aktualizuje zmienione jednym commitem przez svnmucc. Nie wysyła lokalnych usunięć. Ścieżkę skasowaną w repo domyślnie pomija; -restore-set pozwala ją jawnie przywrócić, gdy nadal istnieje lokalnie. -reverse-reconcile-set zamiast tego doprowadza lokalny folder do jednej dostępnej rewizji repo, również usuwając lokalny nadmiar, bez commitu. Obie dodatkowe flagi wykluczają się i wymagają -nwc. Faza lokalnego zastosowania odwrotnego uzgodnienia nie jest atomowa; po przerwaniu uruchom ją ponownie.

To zachowanie programu, a nie zawężenie praw na serwerze. Zwykła aktywacja desktopowa zachowuje nadane prawa także wtedy, gdy jej klucz wykorzysta inny klient. Dla -nwc URL w konfiguracji musi wskazywać korzeń repo. Dowiązania symboliczne i pliki nieregularne w źródle są odrzucane.

Producent i cron

Klienta uruchamiaj po pomyślnym zakończeniu programu tworzącego pliki. Zachowaj łańcuch &&, żeby błąd producenta nie uruchomił FileES. Cron użytkownika może wykonać jeden przebieg według harmonogramu; dodatkowy demon nie jest potrzebny.

ksefuck && /usr/local/bin/filees-client publish faktury-2026 --message ksefuck

Profil przygotuj jako użytkownik crona. publish sprawdza świeże prawa na serwerze i odmawia offline, po cofnięciu praw lub zmianie bindingu. Dodaje/aktualizuje jednym atomowym commitem, bez propagowania lokalnych usunięć i bez przywracania zdalnie skasowanych plików. Postęp podaje etap i liczby. CLI zapewnia soft limit uchwytów dla SVN, lecz przy niewystarczającym hard limicie odmawia przed commit; nie dzieli partii. Polecenia nie instalują crona. Podpisana paczka r2016 nie ma autoconfig/publish ani install/update — potrzebne jest nowe wydanie.

Ścieżki i harmonogram dopasuj do wdrożenia. Powtórny przebieg bez zmian nie tworzy nowego commitu. Błąd producenta zatrzymuje łańcuch; nie zmieniaj && na bezwarunkowe wywołanie klienta.

Import i Whale

dump-load --profile PROFIL --dump DUMP --name NAZWA --target NOWA_WC --state PRYWATNY_STAN tworzy nowe repozytorium i nową kopię roboczą. Aktywacja musi mieć prawo tworzenia repo. Gdy wynik jest niepewny, ponów dokładnie te same argumenty i katalog stanu; zapisane ID operacji wznawia ten sam import. Istniejącego celu program nie nadpisuje.

whale-put publikuje duży plik. Przy pobieraniu whale-get-quote podaje rozmiar i ID operacji, a whale-get-confirm --id ID jawnie uruchamia transfer. whale-status, whale-retry i whale-resume korzystają z tego samego prywatnego katalogu stanu.

Przerwania i ponowienia

Przed pierwszym uruchomieniem rozpakuj archiwum właściwej platformy i zapewnij dostęp do SVN oraz SSH w ścieżkach z konfiguracji. Stronę podręcznika można czytać przez man -M /ścieżka/do/pakietu/share/man filees-client. Polecenia zwracają 0 przy sukcesie, 1 przy błędzie operacji i 2 przy błędnych argumentach. W cron używaj pełnych ścieżek.

Przy Whale sukces pobrania oznacza sprawdzony plik oraz potwierdzenie zwolnienia serwerowego cache i rezerwacji miejsca. Plik może już być na dysku, gdy operacja jeszcze czeka na potwierdzenie. Sprawdź whale-status --id ID; po błędzie użyj whale-retry --id ID, po przerwaniu procesu whale-resume --id ID, zawsze z tym samym profilem i katalogiem stanu. Klient sprawdzi plik i ponowi zwolnienie bez pobierania go drugi raz.

Po konflikcie zwykłej kopii roboczej rozstrzygnij go w SVN przed ponowieniem sync. Po przerwaniu odwrotnego uzgodnienia ponów ten sam przebieg; zastosowanie całego drzewa lokalnego nie jest atomowe.
