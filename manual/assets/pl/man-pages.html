filees-admin(8)

bilety administracyjne, odwołanie i zamknięcie wymazania

Rola

filees-admin is the operator command for onboarding tickets and a small set of fail-closed administrative actions. It writes structured JSON to standard output and diagnostics to standard error. It must run with effective user _filees-state . Creating a ticket as root produces a root-owned mode 0600 file that the set-id onboarding entry intentionally cannot read.

version is answered before the configuration is opened, so a stale binary can be identified even when server.json is suspect.

Repository create, grants, public shares and realm removal are desktop control-plane operations, not extra filees-admin verbs.

Wywołanie

filees-admin [-config path] ticket create mailbox [--ttl duration] [--join-realm-alias alias]
filees-admin [-config path] ticket resend --ticket-id uuid
filees-admin [-config path] ticket revoke --ticket-id uuid
filees-admin [-config path] ticket list
filees-admin [-config path] operation inspect --operation-id uuid
filees-admin [-config path] client revoke --client-id uuid [--reason text]
filees-admin [-config path] client revoke-realm --realm-id uuid [--reason text]
filees-admin [-config path] repo transfer-owner --repo-id uuid --realm-id uuid
filees-admin [-config path] erasure complete --operation-id uuid [--partially-retained]
filees-admin version

Flagi i czasowniki

Flaga / czasownikZnaczenie
ticket createIssue a one-time invitation to mailbox and send it immediately. The mailbox must come before any flag. Without --join-realm-alias the ticket authorises a new realm. With the flag the server resolves the immutable alias now and stores the approved realm ID; the client never submits that ID. The invitation capability is not printed.
ticket resendReplace a failed delivery capability without changing recipient or TTL.
ticket revokeDelete an unused ticket. A claimed ticket has already been replaced by an operation bundle.
ticket listList remaining tickets. Names are sha256 mailbox so the file name does not reveal the address.
operation inspectShow one onboarding operation.
client revokeWrite a durable revoking record, drop generated SSH/SVN access, then commit the revoked client. An identical retry is idempotent; a different reason is rejected.
client revoke-realmRevoke every installation of a realm with the same sequence.
repo transfer-ownerChange owner_realm_id and regenerate data-authz. Existing grants issued by the previous owner are not touched.
erasure completeClose a data-erasure request after the operator has verified backup retention. --partially-retained records that policy still requires some copies.

Przykłady

Create a new-realm invitation:

$ doas -u _filees-state filees-admin ticket create user@example.com

Authorise another desktop in an existing realm:

$ doas -u _filees-state filees-admin ticket create user@example.com \
    --join-realm-alias acme --ttl 24h

filees-operation(8)

domknięcie claimów onboardingu i wygaszanie niedokończonych operacji

Rola

filees-operation finishes crash-visible onboarding state. It must run as _filees-state .

recover scans operations/ for .claim-*.json files. A claim-as-ticket is turned into a bundle and renamed. A claim-as-bundle is only renamed. It also expires unfinished operations whose TTL has elapsed, redacts OTP and delivery address, removes expired staged keys, and resumes confirmed realm-removal journals after every client credential has been revoked. Active clients are not expired by the onboarding TTL. The command is idempotent.

inspect prints one operation bundle.

Wywołanie

filees-operation [-config path] recover
filees-operation [-config path] inspect --operation-id uuid

Flagi i czasowniki

Flaga / czasownikZnaczenie
[-config path] recoverZe SYNOPSIS.
[-config path] inspect --operation-id uuidZe SYNOPSIS.

Przykłady

$ doas -u _filees-state filees-operation recover

filees-onboard(8)

zużywa zaproszenie i tworzy kolejkę OTP; sam nie wysyła poczty

Rola

filees-onboard reads one JSON invitation request from standard input and atomically creates or resumes the onboarding operation. It does not send mail. filees-bootstrap-entry(8) calls filees-onboard take and then exactly one filees-mail(8) send .

The command is a short-lived tool. It has no listener and accepts no extra arguments.

Wywołanie

filees-mail(8)

jedna pozycja skrzynki wychodzącej albo pętla poczty udziałów publicznych

Rola

send claims one pending control-plane mail job and submits it through the configured SMTP relay. It is the one-shot drain used after filees-admin(8) ticket actions and after filees-bootstrap-entry(8) . Onboarding, realm-removal and data-erasure jobs share this path.

Delivery states are pending , sending , queued , and failed . A 4xx leaves the job pending and preserves the OTP. A 5xx marks failed and redacts the OTP. The Message-ID is derived from CreatedAt , so a lost 250 can be retried safely.

public-loop is not an operator command. filees-public-authority(8) supervises it as an isolated child. The child loads the SMTP secret and drains only the Public Shares outbox. The authority process never receives that secret. If the child dies, the authority exits.

Wywołanie

filees-mail [-config path] send
filees-mail [-config path] public-loop

Flagi i czasowniki

Flaga / czasownikZnaczenie
[-config path] sendZe SYNOPSIS.
[-config path] public-loopZe SYNOPSIS.

Przykłady

Retry a 4xx invitation:

$ doas -u _filees-state filees-mail send

filees-bootstrap-entry(8)

publiczne wymuszone polecenie pierwszego wejścia

Rola

filees-bootstrap-entry is the sshd(8) forced command for _filees-onboard . It accepts no arguments. The compiled-in bootstrap public key is a public capability: it can only reach this command, and forwarding is disabled.

The command performs exactly two steps: filees-onboard(8) take one filees-mail(8) send attempt

It does not enumerate tickets and does not expose whether an address is free.

filees-entry(8)

wymuszone polecenie tunelu po kodzie jednorazowym

Rola

filees-entry is the sshd(8) forced command for _filees-tunnel . It accepts only the literal remote command filees tunnel-v1 .

BSD Auth has already compared the OTP. filees-entry then claims the operation bundle, confirming the reverse forward to 127.0.0.1:42000 , and execs filees-worker(8) for the rest of the activation. The OTP is not taken from the environment; sshd(8) does not propagate BSD Auth setenv values to the forced command.

filees-ssh-auth(8)

styl BSD Auth porównujący kod jednorazowy dla tunelu

Rola

filees-ssh-auth is installed as /usr/libexec/auth/login_-filees with owner _filees-state , group auth and mode 4550. sshd(8) invokes it for _filees-tunnel keyboard-interactive authentication.

The OTP is received on file descriptor 3, not from the environment. A successful comparison advances the operation bundle from awaiting_tunnel to tunnel_authorized . filees-entry(8) then claims that state.

The _filees-tunnel password field must not be * ; BSD Auth rejects such accounts before a local style can run. The OpenBSD installer writes an unknowable random hash.

filees-client-entry(8)

dyspozytor per-klucz: svnserve albo jeden ticket control-plane

Rola

filees-client-entry is the set-id dispatcher installed for installation-key sessions. sshd(8) selects the account _filees-client or _filees-data and the per-key command= line. filees-client-entry accepts exactly two original commands: Tunnel-mode Subversion. One authenticated control-plane ticket, then filees-worker(8) .

Before a control-plane ticket it runs filees-service-wc-corrector(8) so a previous root-owned administrative svn cannot leave the service working copy unreadable to _filees-state .

The image is _filees-state : _filees-access mode 4550. It is not a general shell.

filees-worker(8)

jedna uwierzytelniona akcja serwera i wyjście

Rola

filees-worker is exec'd once per authenticated deploy or control-plane ticket. It is root : wheel mode 0555 and has no resident service. The next operation execs the current image.

It is the only process that mutates canonical service-repository records, data repositories, grants, editing policy and Public Shares channel state. It publishes through a path-scoped Subversion commit under the shared service-WC lock. Unversioned leftovers from a killed older binary are reconciled before the next scan.

Do not run filees-worker as root against the service working copy. Root can bypass the 0700 directory mode and then leaves root-owned pristine objects in .svn .

Wywołanie

Flagi i czasowniki

Przykłady

filees-service-wc-corrector(8)

naprawa właściciela kopii roboczej repozytorium serwisowego

Rola

filees-service-wc-corrector is a tiny set-id-root helper. It accepts no arguments. It walks the configured service working copy and the shared .service-wc.lock , and runs lchown on any path whose UID or GID is not the state account. It never changes modes or content.

Effective UID 0 is required. The state-account UID must not be 0. The walk refuses to cross a filesystem boundary and refuses unsupported file types.

filees-client-entry(8) invokes filees-service-wc-corrector before a control-plane ticket. Ordinary workers remain unprivileged.

The installed image is root : _filees-access mode 4550.

Wywołanie

Przykłady

filees-install(8)

podpisana aktualizacja binarek serwera z FILEES-BIN

Rola

filees-install updates installed FileES server binaries from a separate binary release repository. It is not a package manager and does not create a local Subversion working copy. It fetches channel and manifest documents with svn cat , verifies the OpenBSD signify signature against a public key embedded at build time, checks SHA-256 hashes, records a durable pre-image journal, and replaces targets atomically.

Manifest schema v2 signs owner, group and full mode, including set-id bits. Install and rollback restore content, UID, GID and mode. The apply lock is exclusive; a SIGSTOP then SIGKILL chaos test on an unlocked earlier build panicked the OpenBSD kernel.

--adopt records an existing installation as the managed baseline. It changes no files and accepts the host only when every managed path matches the signed hash, owner, group and mode.

A release older than the recorded high-water mark is refused unless --allow-rollback is also given. That flag is a deliberate administrative act, never the ordinary update.

The running /etc/filees/server.json is not overwritten.

Wywołanie

filees-install [-c file] [--check-config] [--check [release]] [--dry-run [release]] [--apply [release]] [--adopt [release]] [--rollback] [--revert-to release] [--purge] [--wipe-state] [--allow-rollback] [--yes] [--talkative]

Flagi i czasowniki

Flaga / czasownikZnaczenie
-c fileRead filees-install(8) configuration from file . The default is /etc/filees/install.conf .
--check-configPrint the resolved configuration and exit.
--checkFetch the channel and print the install plan without downloading payloads.
--dry-runBuild the full plan, including config-contract drift, without installing.
--applyDownload, verify, stage, journal and install the channel head or release .
--adoptVerify and adopt without modification.
--rollbackRestore the previous locally installed release from the journalled pre-image.
--revert-to releaseInstall a named release such as r543 .
--purgeRemove files this installer manages. Keeps /var/filees and /etc/filees unless --wipe-state is also given.
--allow-rollbackPermit installing a release older than the local high-water mark.
--yesAnswer yes to interactive prompts.
--talkativePrint Sq [SECURITY] unveil and pledge diagnostics.

Przykłady

Adopt a host that already matches signed r543:

$ doas filees-install --adopt r543

Plan and apply the configured channel:

$ doas filees-install --dry-run
$ doas filees-install --apply

filees-rotate(8)

jawna zmiana generacji repozytorium FSFS

Rola

filees-rotate replaces a hot repository with a new generation. The new generation has a new UUID and starts at revision 1 equal to a complete dump of the old HEAD, including versioned properties such as svn:needs-lock . It inherits conf/ and hooks/ , is verified with svnadmin and a tree comparison, then swapped atomically. The old generation becomes a frozen, commit-blocked FSFS archive. Existing working copies do not survive the UUID change.

For the FileES append-only profile, rotation is a retention tool, not a performance tool. There is no built-in scheduler. Running filees-rotate is an operational decision. The same staging and swap machinery is reused by LOAD_REPOSITORY_DUMP .

Wywołanie

filees-rotate -repo path -archive directory [-size threshold] [-age-days n] [-dry-run] [-force] [-break-locks] [-dump-depth n]

Flagi i czasowniki

Flaga / czasownikZnaczenie
-repo pathAbsolute path of the hot repository.
-archive directoryArchive directory on the same filesystem as the repository, so the swap is a rename.
-size thresholdRotate when packed size reaches this. Default 25GiB .
-age-days nRotate when revision 1 is older than n days. Default 365.
-dry-runPrint the decision without rotating.
-forceRotate regardless of triggers.
-break-locksProceed despite active locks. This destroys live edit passports.
-dump-depth nAlso archive a gzip dump of the last n revisions before HEAD. Zero, the default, writes no extra dump. The frozen FSFS archive is canonical.

Przykłady

$ filees-rotate -repo /STORAGE01/filees-repos/UUID \
    -archive /STORAGE01/filees-archive -dry-run

filees-public-authority(8)

autorytet udziałów publicznych i kody odbiorców

Rola

filees-public-authority is the authoritative side of Public Shares. It listens on a Unix socket or loopback TCP. It never terminates TLS. It fetches leaves with svnlook and pushes them to filees-links(8) .

It supervises filees-mail(8) public-loop as a required child. The child holds the SMTP secret. filees-public-authority does not. On SIGTERM or SIGINT it closes the HTTP server, terminates the child and waits, then exits, so an rcctl(8) restart cannot leave an orphan poller.

Recipient OTP epochs, attempt counters and invitation hashes live under the Public Shares state root. Revoke and delete cut access immediately and drop pending mail. They do not yet garbage-collect inactive epoch files; those files contain no mailbox and no plaintext code.

Wywołanie

filees-links(8)

publiczna powierzchnia FastCGI udziałów, bez poświadczeń

Rola

filees-links serves the credential-free public HTML and file/ZIP downloads. It reads filees-public-links(5) , not filees.conf(5) . It owns only a temporary cache. It asks filees-public-authority(8) for each leaf.

The process uses no JavaScript, sets no cookies, and sends Cache-Control: no-store plus a hashed Content-Security-Policy. Unknown, revoked and deleted addresses share one branded HTTP 404 that does not echo the requested path.

Listing iterates the channel's declared object map. It does not walk the repository tree. See the Public Shares chapter of the HTML manual.

Wywołanie

filees-mobile-v1(8)

wejście protokołu mobilnego (odczyt udziału, zapis pod mobile-uploads/)

Rola

filees-mobile-v1 is the set-id entry for _filees-mobile . The installed image is _filees-state : _filees-access mode 4550, the same class as filees-client-entry(8) .

The mobile client is paired from an already activated desktop. It inherits that desktop's repository list once. The phone may read a granted share and write only under mobile-uploads/ . A new path is unique-append. The same path under mobile-uploads/ with different content becomes a new Subversion revision. UPLOAD_TREE ingests a marked zip as one commit; an unmarked zip is rejected as a whole. The mobile projection does not receive editing_policy .

sshd(8) uses the shared authorized_keys file. The per-key command= line selects this image. There is no ForceCommand on the _filees-mobile match block.

filees-recovery-entry(8)

wydawanie archiwów po usunięciu strefy, jedna operacja

Rola

filees-recovery-entry is the set-id session entry for _filees-recovery . A second image of the same binary is installed as /usr/local/libexec/filees/filees-recovery-authorize owner root , group wheel , mode 0555 because sshd(8) requires every AuthorizedKeysCommand component to be root-owned. Key lookup and session service are therefore distinct executables.

The client presents a per-operation Ed25519 recovery key from the .fkr kit written during realm removal. The authorise helper emits a restricted key line bound to that one operation ID and refuses it after download_until . The session protocol is exactly two verbs:

list <operation_id>
get  <operation_id> <archive_id>

The entry is read-only stdio rpath and never sees a private key. The key grants no SVN access, no shell and no other operation.

Wywołanie

Brak przykładu w mandoc; poniżej uczciwe wywołanie z opisu.
