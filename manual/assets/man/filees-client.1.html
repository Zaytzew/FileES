NAME

filees-client — run one FileES client operation without a background daemon

SYNOPSIS

filees-client version

filees-client autoconfig [--profile path | --activation directory] [--state-root directory] [--server name] [--repo name] [--source directory] [--name name] [--config-root directory] [--svn path] [--svnmucc path] [--ssh path] [--timeout duration]

filees-client publish name [--config-root directory] [--message text] [--timeout duration]

filees-client install | update [--prefix directory] [--check] [--svn path] [--timeout duration]

filees-client activate-begin --server-id id --server address --known-hosts path --state-root path --email address

filees-client activate-finish | activate-resume --server-id id --server address --known-hosts path --state-root path [--remote-port port]

filees-client checkout --config path --wc id [--timeout duration]

filees-client sync --config path --wc id [--timeout duration] [--message text] [--nwc] [--restore-set | --reverse-reconcile-set]

filees-client dump-load --profile path --dump path --name name --target path --state path [--svn path] [--ssh path] [--timeout duration]

filees-client whale-put | whale-get-quote | whale-get-confirm | whale-status | whale-retry | whale-resume --profile path --state path [--id uuid] [--repo uuid] [--path repository-path] [--source path] [--dest path] [--revision number] [--timeout duration]

DESCRIPTION

filees-client is a one-shot FileES client for Linux and OpenBSD. It exits after one operation and may be called by a user's cron job. It uses an activated FileES identity and a pinned SSH host key. It is distributed separately from the desktop daemon and the server bundle. version prints the standalone client version and the source revision.

install and update verify and install the latest signed standalone CLI release. They require a distribution build containing the trusted release key and a system Subversion client. Before executing the initial distribution, verify its manifest signature with the publisher's trusted public key and check the archive size and SHA-256. The dedicated CLI channel cannot install desktop or server bundles. --prefix defaults to /usr/local and must be an absolute directory without symbolic links. Use the same prefix for every subsequent update. --check verifies metadata without downloading the archive or replacing files; it still creates private update state and requires write access to the prefix. --svn selects the Subversion executable, otherwise found in PATH. The default installation timeout is 30 minutes.

Installation checks signatures, platform binding, expiry, archive size and SHA-256, and exactly the binary, README and manual. Each file is replaced atomically, with the executable replaced last. An interruption may leave newer documentation beside the old program; repeat the command to finish. The durable rollback watermark is saved before replacement and permits retrying the same release while refusing older releases. The installer's compiled source revision also sets a minimum on first install. The updater preserves one previous executable and one verified archive. It does not alter activation, configuration, working copies or cron, and does not stop a running sync operation.

autoconfig uses an existing activated profile or an older CLI activation directory, without another OTP or copying identity keys. With no repository name it lists the live server repositories. Select an exact, unambiguous repository display name and an explicit absolute source directory; the source is canonicalized and never widened to its parent. Only active, writable ordinary repositories without mandatory edit locks qualify. The default activation root is XDG_DATA_HOME/filees/servers or ~/.local/share/filees/servers; use --state-root or --server to select another. Private jobs are stored below XDG_CONFIG_HOME/filees-cli or ~/.config/filees-cli. Both commands accept --config-root outside the source. An existing root must already be private. Tool paths are discovered once and stored as absolute paths for cron. Repeating the same configuration is idempotent; another binding needs another name.

publish name refreshes the server projection and checks saved client, realm and repository identities, URL, permissions and monotonic generation before publishing. Offline or revoked access refuses publication. It uses the no-working-copy publisher, preserving remotely deleted paths and never propagating local deletions. It does not accept restoration or reverse-reconcile flags. Progress on stderr reports stages and counts without file names. All changed files are committed atomically; the process automatically sets the inherited descriptor soft limit for svnmucc, requiring changes plus 64 spare descriptors within the hard limit. An insufficient hard limit refuses before commit; publication is never split. The timeout defaults to 30 minutes including permission refresh; an uncertain commit reply permits an additional 30-second confirmation. No command installs cron.

activate-finish and activate-resume use the reverse port saved by onboarding. An old passport without a saved port requires explicit --remote-port.

checkout creates a working copy at the path selected by --wc. Without --nwc, sync requires that working copy. It updates, adds new files, propagates local deletions, and commits changes. Conflicts stop the operation for manual resolution.

sync --nwc uses a plain directory and commits new or changed files through svnmucc(1). The long alias is --no-working-copy. It never propagates local deletions. By default it does not restore paths deleted from the repository; --restore-set explicitly enables restoration of source-present paths. --reverse-reconcile-set instead downloads one repository revision into the plain directory, overwrites changed files and removes local paths absent from the accessible repository view, without committing. The two set flags are mutually exclusive and require --nwc. No form of --nwc creates a .svn directory. These are client behaviours, not server-enforced permissions: the activation retains its ordinary grants.

dump-load imports one Subversion dump into a newly created repository and a new working copy. Both --target and the private --state directory must be dedicated to this import. On an uncertain result, repeat exactly the same command with the same --state; the stored operation ID prevents creating another repository. The existing repository and working copy are never overwritten. The activation needs permission to create repositories.

whale-put publishes a source file through FileES Whale. whale-get-quote returns an operation ID and size without downloading. After reviewing the quote, whale-get-confirm with that ID starts the download to a new destination. whale-status, whale-retry, and whale-resume read or continue operations in the same private state directory. No Whale command starts a daemon. The quote reports size and operation ID; downloading requires a separate explicit confirmation.

A successful confirmed download includes verification of the destination and confirmation that the server released its download cache and reservation. The destination may already exist while the operation is still verifying or has failed to receive that confirmation. Inspect it with whale-status and use whale-retry after a failure, or whale-resume after a process interruption. The same operation checks the existing file and retries release without downloading it again.

CONFIGURATION

The INI file named by --config contains ‘tools’ (absolute paths for svn, svnmucc, ssh and log_dir), ‘realm’ (identity, known_hosts, host, port and optional only), and one or more ‘wc id’ sections (path and repository-root URL). The optional only value is an explicit allow-list such as “!invoices !archive”. The journal directory must exist and be outside a --nwc source. The CLI never takes an arbitrary source directory or repository URL from a sync command line.

FILES

/etc/filees/filees-client.conf
Example invocation profile; the actual path is supplied by --config.
/var/log/filees-client
Default private journal directory; create it before running the client.
/usr/local/share/filees-client-update
Private update state (mode 0700), lock, verified archive cache and previous-filees-client. Below a custom prefix, the same relative path is used. Do not remove this state to bypass rollback protection.
/usr/local/man/man1/filees-client.1
Installed manual on OpenBSD; Linux uses /usr/local/share/man/man1/filees-client.1.
state/job.json
Durable dump-load identity, stored below the chosen --state directory.

EXIT STATUS

The filees-client utility exits 0 on success, and >0 if an error occurs. Usage errors return 2. Transport, repository, journal and interrupted-operation errors return 1.

EXAMPLES

doas ./bin/filees-client install
doas /usr/local/bin/filees-client update --check
sudo /usr/local/bin/filees-client update
filees-client sync --config /etc/filees/filees-client.conf --wc invoices -nwc
filees-client sync --config /etc/filees/filees-client.conf --wc invoices -nwc -restore-set
filees-client sync --config /etc/filees/filees-client.conf --wc invoices -nwc -reverse-reconcile-set
filees-client dump-load --profile /home/user/.filees/client-profile.json \
  --dump /home/user/archive.dump --name Invoices-Archive \
  --target /home/user/archive-wc --state /home/user/.filees/import-001

After a producer has completed successfully, cron may call the client with && so a failed producer cannot publish a partial output.

SEE ALSO

CAVEATS

The repository path in a --nwc profile must be its root. Symbolic links and non-regular source files are refused. Reverse reconciliation stages downloaded files before changing the local directory, but application of the complete tree is not atomic; rerun it after an interruption. Keep activation keys, profiles and operation state outside published folders.
