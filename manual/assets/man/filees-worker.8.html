NAME

filees-worker — execute one authenticated FileES server action and exit

SYNOPSIS

filees-worker deploy

filees-worker repository-control client-id

filees-worker whale-v1

filees-worker upload-reap

filees-worker passport-reap [-config path] [--check]

filees-worker upload-seed-reject -alias realm-alias

filees-worker mobile-onboard

filees-worker mobile-proof operation-id client-id

filees-worker mobile-finish operation-id client-id

DESCRIPTION

filees-worker is exec'd once per authenticated deploy or control-plane ticket, dispatching on its first argument to a subcommand; maintenance modes are also invoked by cron.

deploy
default path, also reached with no subcommand at all; reads a tunnel session from stdin and runs the desktop/server bootstrap deploy.
repository-control
reads one signed control/v1 ticket from stdin scoped to client-id and mutates canonical service-repository records, data repositories, grants, editing policy or Public Shares channel state, as described below.
whale-v1
serves one framed Whale PUT window, status or commit request, as described below.
upload-reap
the operator cron exception described below.
passport-reap
performs one bounded, server-clock cleanup pass over registered passports, without a connected client or service-WC update. Run as _filees-state, not root. Busy locks are not queued; errors are reported and the next scheduled invocation resumes durable state without force. The optional --check reads the last maintenance status and fails for missing, running, failed, corrupt or stale (over five minutes) state. The package provides an example crontab but does not enable it. Expiry is operational, at the next successful pass, not a strict SVN deadline.
upload-seed-reject
plants one harmless EICAR reject in the waiting room of realm-alias so the owner can receive the quarantine projection without a real infected upload. Run as _filees-state, same as upload-reap.
mobile-onboard
reads a JSON push payload from stdin and stages a mobile client's activation grant; exec'd by filees-entry(8)'s mobile push branch.
mobile-proof
records that a freshly generated mobile installation key proved possession by connecting; exec'd by filees-mobile-v1(8)'s proof branch.
mobile-finish
completes a mobile onboarding operation for client-id; exec'd by filees-mobile-v1(8)'s finish branch.
It is root: wheel mode 0555 and has no resident service. The next operation execs the current image.

It is the only process that mutates canonical service-repository records, data repositories, grants, editing policy and Public Shares channel state. It publishes through a path-scoped Subversion commit under the shared service-WC lock. Unversioned leftovers from a killed older binary are reconciled before the next scan.

In Whale mode it serves one framed PUT window, status or commit request. It keeps the exact durable offset and immutable generation identity in a server-owned journal, checks the current client projection, and publishes only through svnmucc to the reserved .filees-whales namespace. The worker establishes its own restricted filesystem profile after the gated session child execs it.

Do not run filees-worker as root against the service working copy. Root can bypass the 0700 directory mode and then leaves root-owned pristine objects in .svn.

filees-worker upload-reap is the operator exception to the one-shot deploy contract. It claims ready intake jobs, runs upload.av_command, and commits a clean payload into upload_repo or copies a rejected payload into the trash tree. Run it as _filees-state, never as root:

* * * * * /usr/local/libexec/filees/filees-worker upload-reap -config /etc/filees/server.json >/dev/null
The installer does not install that crontab. Intake job directories are 0770 _filees-links: _filees-public so _filees-state (a member of _filees-public) can read them. av_command runs as the reaper user and must be able to open the payload; clamscan does that, clamdscan does not unless _clamav can also read the job directory.

filees-worker upload-seed-reject -alias alias plants one EICAR test file in trash_root for that realm's waiting room so the owner can receive the quarantine projection without a live infected upload. It does not run av_command and does not commit into trash_repo; the owner list reads the waiting-room filesystem. upload-reap also treats the EICAR test file as infected even when the helper exits 0.
