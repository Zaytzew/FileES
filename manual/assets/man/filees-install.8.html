NAME

filees-install — update FileES server binaries from a signed FILEES-BIN repository

SYNOPSIS

filees-install [-c file] [--check-config] [--check [release]] [--dry-run [release]] [--apply [release]] [--adopt [release]] [--rollback] [--revert-to release] [--purge] [--wipe-state] [--allow-rollback] [--yes] [--talkative]

DESCRIPTION

filees-install updates installed FileES server binaries from a separate binary release repository. It is not a package manager and does not create a local Subversion working copy. It fetches channel and manifest documents with svn cat, verifies the OpenBSD signify signature against a public key embedded at build time, checks SHA-256 hashes, records a durable pre-image journal, and replaces targets atomically.

Manifest schema v2 signs owner, group and full mode, including set-id bits. Install and rollback restore content, UID, GID and mode. The apply lock is exclusive; a SIGSTOP then SIGKILL chaos test on an unlocked earlier build panicked the OpenBSD kernel.

--adopt records an existing installation as the managed baseline. It changes no files and accepts the host only when every managed path matches the signed hash, owner, group and mode.

A release older than the recorded high-water mark is refused unless --allow-rollback is also given. That flag is a deliberate administrative act, never the ordinary update.

Operator configurations are not replaced by examples. Explicit signed configuration contracts may trigger journalled, selective migrations of /etc/filees/server.json and /etc/filees/public-links.json. Unknown fields and custom storage paths are preserved.

The public_downloads_dir key in the install section chooses the base for migrating legacy Public Shares temporary roots. Default: /var/filees-downloads. Authority staging and frontend cache remain independently configurable in their JSON files. Apply checks capacity and prepares private directories; check and dry-run do not provision them. Existing metadata is not silently corrected and old caches are not deleted.

An older running installer must first update its binary with the existing config, then be invoked again after adding the new key. Review the migration plan and apply the same signed release before restarting Public Shares. The release includes examples/public-storage-migration.md with this bridge.

OPTIONS

-c file
Read the configuration described under CONFIGURATION from file. The default is /etc/filees/install.conf.
--check-config
Print the resolved configuration and exit.
--check
Fetch the channel and print the install plan without downloading payloads.
--dry-run
Build the full plan, including config-contract drift, without installing.
--apply
Download, verify, stage, journal and install the channel head or release.
--adopt
Verify and adopt without modification.
--rollback
Restore the previous locally installed release from the journalled pre-image.
--revert-to release
Install a named release such as r1042.
--purge
Remove files this installer manages. Keeps /var/filees and /etc/filees unless --wipe-state is also given.
--allow-rollback
Permit installing a release older than the local high-water mark.
--yes
Answer yes to interactive prompts.
--talkative
Print ‘[SECURITY]’ unveil and pledge diagnostics.

CONFIGURATION

/etc/filees/install.conf is a plain section.key = value file. Blank lines and lines beginning with ‘#’ are ignored. An unknown key is a hard error naming the line, so an obsolete setting stops the tool rather than being silently ignored. Booleans accept 1, yes, true, on and their negatives. Every path must be absolute.

repo.url
Base URL of the FILEES-BIN release repository. A trailing slash is trimmed. Schemes accepted: svn, svn+ssh, https.
repo.channel
Release channel, default stable.
repo.platform
Target triple, default the host's own GOOS-GOARCH.
repo.svn
svn(1) binary, default svn from PATH.
local.state_dir
Recorded release, high-water mark and journal. Default /var/filees/install-state.
local.stage_dir
Staging for fetched artifacts, default /var/filees/install-stage.
local.backup_dir
Pre-image copies used by rollback, default /var/filees/install-backup.
local.lock_path
Exclusive apply lock, default /var/run/filees-install.lock.
install.sbin_dir, install.libexec_dir
Operator commands and short-lived workers. Defaults /usr/local/sbin and /usr/local/libexec.
install.sysconf_dir
Configuration root, default /etc/filees.
install.sshd_conf_dir, install.ssh_keys_dir, install.login_conf_dir
Host integration directories. Defaults /etc/ssh/sshd_config.d, /etc/ssh and /etc/login.conf.d.
install.data_dir
Server state root, default /var/filees.
install.public_downloads_dir
Public Shares storage root, default /var/filees-downloads. Its parent must be root-owned and not group- or other-writable; the tool refuses otherwise, because this directory holds files served to the public.
policy.default_action
Action taken when the command line names none: check (default), dry-run or apply.
policy.config_drift
What a locally modified managed configuration file does: block (default), warn or ignore.
policy.orphan_files
What an installed file absent from the new manifest does: keep (default), warn or remove.
policy.interactive
Ask before applying. Default on; --yes overrides it for one run.
policy.require_hash
Refuse an artifact whose SHA-256 does not match the manifest. Default on. Turning it off is not an ordinary operation.
policy.verify_signature
Verify the release envelope against the key compiled into this binary. Default on.
policy.talkative
Print sandbox diagnostics. Default off.
security.signify
Accepted and ignored. Signature verification moved in process on 2026-09-09, so no external program is named any more. The key is still accepted so that a deployed configuration keeps loading.

FILES

/etc/filees/install.conf
Updater configuration.
/var/filees/install-state
Recorded release, high-water mark and journal.
/var/run/filees-install.lock
Exclusive apply lock.

EXIT STATUS

The filees-install utility exits 0 on success, and >0 if an error occurs.

EXAMPLES

Adopt a host whose files already match a signed baseline release:

$ doas filees-install --adopt r1042

Plan and apply the configured channel:

$ doas filees-install --dry-run
$ doas filees-install --apply
