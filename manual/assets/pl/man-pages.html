Wyciąg CLI z mandoc

To jest wyciąg Tech ze źródeł OpenBSD mandoc w docs/man. Każde polecenie serwera jest tu od roli, wywołania, flag i przykładów. Angielski jest kanoniczny: tak przyjmują binarki. Rola jest po polsku. Klient pulpitu filees nie ma jeszcze strony mandoc — zobacz User howto pulpitu.

Wymuszone polecenia odpala sshd. Są na liście, żeby było widać sztafetę, nie dlatego, że operator je wpisuje. Pliki konfiguracji filees.conf(5) i filees-public-links(5) są wskaźnikami, nie poleceniami.

filees-admin(8)

bilety administracyjne, odwołanie i zamknięcie wymazania

Rola

filees-admin to polecenie operatora obsługujące bilety onboardingu oraz niewielki zestaw fail-closed działań administracyjnych. Zapisuje ustrukturyzowany JSON na standardowe wyjście, a diagnostykę na standardowe wyjście błędów. Musi działać z efektywnym użytkownikiem _filees-state . Utworzenie biletu jako root tworzy plik należący do roota, w trybie 0600, którego set-id'owe wejście onboardingu celowo nie potrafi odczytać.

version odpowiada, zanim otwarta zostanie konfiguracja, więc nieaktualną binarkę można rozpoznać nawet wtedy, gdy server.json budzi podejrzenia.

Utworzenie repozytorium, granty, udziały publiczne i usunięcie strefy to operacje control-plane pulpitu, a nie dodatkowe czasowniki filees-admin.

Wywołanie

filees-admin [-config path] ticket create mailbox [--ttl duration] [--join-realm-alias alias]
filees-admin [-config path] ticket resend --ticket-id uuid
filees-admin [-config path] ticket revoke --ticket-id uuid
filees-admin [-config path] ticket list
filees-admin [-config path] operation inspect --operation-id uuid
filees-admin [-config path] client revoke --client-id uuid [--reason text]
filees-admin [-config path] client revoke-realm --realm-id uuid [--reason text]
filees-admin [-config path] repo transfer-owner --repo-id uuid --realm-id uuid
filees-admin [-config path] erasure complete --operation-id uuid [--partially-retained]
filees-admin version

Flagi i czasowniki

Flaga / czasownikZnaczenie
ticket createIssue a one-time invitation to mailbox and send it immediately. The mailbox must come before any flag. Without --join-realm-alias the ticket authorises a new realm. With the flag the server resolves the immutable alias now and stores the approved realm ID; the client never submits that ID. The invitation capability is not printed.
ticket resendReplace a failed delivery capability without changing recipient or TTL.
ticket revokeDelete an unused ticket. A claimed ticket has already been replaced by an operation bundle.
ticket listList remaining tickets. Names are sha256 mailbox so the file name does not reveal the address.
operation inspectShow one onboarding operation.
client revokeWrite a durable revoking record, drop generated SSH/SVN access, then commit the revoked client. An identical retry is idempotent; a different reason is rejected.
client revoke-realmRevoke every installation of a realm with the same sequence.
repo transfer-ownerChange owner_realm_id and regenerate data-authz. Existing grants issued by the previous owner are not touched.
erasure completeClose a data-erasure request after the operator has verified backup retention. --partially-retained records that policy still requires some copies.

Przykłady

Create a new-realm invitation:

$ doas -u _filees-state filees-admin ticket create user@example.com

Authorise another desktop in an existing realm:

$ doas -u _filees-state filees-admin ticket create user@example.com \
    --join-realm-alias acme --ttl 24h

filees-operation(8)

domknięcie claimów onboardingu i wygaszanie niedokończonych operacji

Rola

filees-operation domyka stan onboardingu widoczny po awarii. Musi działać jako _filees-state .

recover skanuje operations/ w poszukiwaniu plików .claim-*.json . Claim będący biletem jest zamieniany w bundle i przemianowywany. Claim będący już bundlem jest tylko przemianowywany. Polecenie wygasza też niedokończone operacje, którym minął TTL, redaguje OTP i adres dostawy, usuwa wygasłe klucze staged oraz wznawia potwierdzone dzienniki usunięcia strefy po odwołaniu wszystkich poświadczeń klienta. Aktywni klienci nie wygasają przez TTL onboardingu. Polecenie jest idempotentne.

inspect wypisuje jeden bundle operacji.

Wywołanie

filees-operation [-config path] recover
filees-operation [-config path] inspect --operation-id uuid

Flagi i czasowniki

Flaga / czasownikZnaczenie
[-config path] recoverZe SYNOPSIS.
[-config path] inspect --operation-id uuidZe SYNOPSIS.

Przykłady

$ doas -u _filees-state filees-operation recover

filees-mail(8)

jedna pozycja skrzynki wychodzącej albo pętla poczty udziałów publicznych

Rola

send przejmuje jedno oczekujące zadanie poczty control-plane i przekazuje je przez skonfigurowany relay SMTP. To jednorazowe opróżnienie kolejki, używane po akcjach filees-admin(8) ticket oraz po filees-bootstrap-entry(8) . Zadania onboardingu, usunięcia strefy i wymazania danych dzielą tę samą ścieżkę.

Stany dostawy to pending , sending , queued i failed . Odpowiedź 4xx zostawia zadanie w stanie pending i zachowuje OTP. Odpowiedź 5xx oznacza failed i redaguje OTP. Message-ID jest wyprowadzany z CreatedAt , więc zgubione 250 można bezpiecznie ponowić.

public-loop nie jest poleceniem operatora. filees-public-authority(8) nadzoruje je jako izolowane dziecko. Dziecko wczytuje sekret SMTP i opróżnia wyłącznie outbox udziałów publicznych. Proces authority nigdy nie dostaje tego sekretu. Jeśli dziecko umiera, authority kończy działanie.

Wywołanie

filees-mail [-config path] send
filees-mail [-config path] public-loop

Flagi i czasowniki

Flaga / czasownikZnaczenie
[-config path] sendZe SYNOPSIS.
[-config path] public-loopZe SYNOPSIS.

Przykłady

Retry a 4xx invitation:

$ doas -u _filees-state filees-mail send

Nie wylicza biletów i nie zdradza, czy dany adres jest wolny.

filees-entry(8)

wymuszone polecenie tunelu po kodzie jednorazowym

Rola

filees-entry to wymuszone polecenie sshd(8) dla _filees-tunnel . Przyjmuje wyłącznie literalne polecenie zdalne filees tunnel-v1 .

BSD Auth porównał już OTP. filees-entry przejmuje wtedy bundle operacji, potwierdza odwrócone przekierowanie na 127.0.0.1:42000 i wykonuje exec na filees-worker(8) dla reszty aktywacji. OTP nie jest pobierany ze środowiska; sshd(8) nie propaguje wartości setenv BSD Auth do wymuszonego polecenia.

Wywołanie

filees-entry

Flagi i czasowniki

Brak flag — proces nie przyjmuje argumentów operatora.

Przykłady

Brak przykładu w mandoc; poniżej uczciwe wywołanie z opisu.

# sshd forced command for _filees-tunnel
# remote command must be exactly:
filees tunnel-v1

filees-ssh-auth(8)

styl BSD Auth porównujący kod jednorazowy dla tunelu

Rola

filees-ssh-auth jest instalowany jako /usr/libexec/auth/login_-filees , właściciel _filees-state , grupa auth , tryb 4550. sshd(8) wywołuje go dla uwierzytelniania keyboard-interactive konta _filees-tunnel .

OTP jest odbierany na deskryptorze pliku 3, nie ze środowiska. Udane porównanie przesuwa bundle operacji ze stanu awaiting_tunnel do tunnel_authorized . filees-entry(8) przejmuje wtedy ten stan.

Pole hasła _filees-tunnel nie może być * ; BSD Auth odrzuca takie konta, zanim zdąży uruchomić się lokalny styl. Instalator OpenBSD zapisuje niepoznawalny losowy skrót.

Wywołanie

filees-ssh-auth

Flagi i czasowniki

Brak flag — proces nie przyjmuje argumentów operatora.

Przykłady

Brak przykładu w mandoc; poniżej uczciwe wywołanie z opisu.

# installed as /usr/libexec/auth/login_-filees
# sshd keyboard-interactive for _filees-tunnel; OTP on fd 3

filees-client-entry(8)

dyspozytor per-klucz: svnserve albo jeden ticket control-plane

Rola

filees-client-entry to set-id'owy dyspozytor instalowany dla sesji kluczy instalacyjnych. sshd(8) wybiera konto _filees-client albo _filees-data oraz linię command= przypisaną do danego klucza. filees-client-entry przyjmuje dokładnie dwa oryginalne polecenia: Subversion w trybie tunelowym. Jeden uwierzytelniony ticket control-plane, po którym następuje filees-worker(8) .

Przed ticketem control-plane uruchamia filees-service-wc-corrector(8) , żeby wcześniejsze administracyjne svn uruchomione jako root nie zostawiło kopii roboczej usługi nieczytelnej dla _filees-state .

Obraz ma właściciela _filees-state : _filees-access , tryb 4550. To nie jest ogólna powłoka.

filees-worker(8)

jedna uwierzytelniona akcja serwera i wyjście

Rola

filees-worker jest uruchamiany przez exec dokładnie raz na każdy uwierzytelniony deploy albo ticket control-plane. Ma właściciela root : wheel , tryb 0555, i nie ma rezydentnej usługi. Kolejna operacja wykonuje exec na aktualnym obrazie.

To jedyny proces, który zmienia kanoniczne rekordy repozytorium usługi, repozytoria danych, granty, politykę edycji i stan kanałów udziałów publicznych. Publikuje przez commit Subversion ograniczony do ścieżki, pod współdzieloną blokadą service-WC. Niezwersjonowane pozostałości po zabitej starszej binarce są uzgadniane przed kolejnym skanem.

Nie uruchamiaj filees-worker jako root wobec kopii roboczej usługi. Root może obejść tryb katalogu 0700, a potem zostawia w .svn obiekty pristine należące do roota.

Wywołanie

filees-worker

Flagi i czasowniki

Brak flag — proces nie przyjmuje argumentów operatora.

Przykłady

Brak przykładu w mandoc; poniżej uczciwe wywołanie z opisu.

# exec’d once per authenticated ticket; do not run as root
filees-worker
Wymuszone polecenie — odpala je sshd; flag nie wpisujesz

filees-service-wc-corrector(8)

naprawa właściciela kopii roboczej repozytorium serwisowego

Rola

filees-service-wc-corrector to mały set-id'owy helper działający jako root. Nie przyjmuje argumentów. Przechodzi po skonfigurowanej kopii roboczej usługi i współdzielonym .service-wc.lock , i wykonuje lchown na każdej ścieżce, której UID albo GID nie jest kontem state. Nigdy nie zmienia trybów ani zawartości.

Wymagany jest efektywny UID 0. UID konta state nie może być 0. Przejście odmawia przekroczenia granicy systemu plików i odmawia dla niewspieranych typów plików.

filees-client-entry(8) wywołuje filees-service-wc-corrector przed ticketem control-plane. Zwykłe workery pozostają nieuprzywilejowane.

Instalowany obraz ma właściciela root : _filees-access , tryb 4550.

Wywołanie

filees-service-wc-corrector

Flagi i czasowniki

Brak flag — proces nie przyjmuje argumentów operatora.

Przykłady

Brak przykładu w mandoc; poniżej uczciwe wywołanie z opisu.

# no arguments; invoked by filees-client-entry before a ticket

filees-install(8)

podpisana aktualizacja binarek serwera z FILEES-BIN

Rola

filees-install aktualizuje zainstalowane binarki serwera FileES z osobnego repozytorium wydań binarnych. Nie jest menedżerem pakietów i nie tworzy lokalnej kopii roboczej Subversion. Pobiera dokumenty kanału i manifestu przez svn cat , weryfikuje podpis OpenBSD signify wobec klucza publicznego wkompilowanego w czasie budowania, sprawdza skróty SHA-256, zapisuje trwały dziennik pre-image i atomowo podmienia cele.

Schemat manifestu v2 podpisuje właściciela, grupę i pełny tryb, w tym bity set-id. Instalacja i rollback przywracają zawartość, UID, GID i tryb. Blokada apply jest wyłączna; test chaosu SIGSTOP a potem SIGKILL na niezablokowanej wcześniejszej wersji spanikował jądro OpenBSD.

--adopt zapisuje istniejącą instalację jako zarządzaną linię bazową. Nie zmienia żadnych plików i akceptuje hosta wyłącznie wtedy, gdy każda zarządzana ścieżka zgadza się z podpisanym skrótem, właścicielem, grupą i trybem.

Wydanie starsze niż zapisany high-water mark jest odrzucane, chyba że podano też --allow-rollback . Ta flaga jest świadomym działaniem administracyjnym, nigdy zwykłą aktualizacją.

Działający /etc/filees/server.json nie jest nadpisywany.

Wywołanie

filees-install [-c file] [--check-config] [--check [release]] [--dry-run [release]] [--apply [release]] [--adopt [release]] [--rollback] [--revert-to release] [--purge] [--wipe-state] [--allow-rollback] [--yes] [--talkative]

Flagi i czasowniki

Flaga / czasownikZnaczenie
-c fileRead filees-install(8) configuration from file . The default is /etc/filees/install.conf .
--check-configPrint the resolved configuration and exit.
--checkFetch the channel and print the install plan without downloading payloads.
--dry-runBuild the full plan, including config-contract drift, without installing.
--applyDownload, verify, stage, journal and install the channel head or release .
--adoptVerify and adopt without modification.
--rollbackRestore the previous locally installed release from the journalled pre-image.
--revert-to releaseInstall a named release such as r543 .
--purgeRemove files this installer manages. Keeps /var/filees and /etc/filees unless --wipe-state is also given.
--allow-rollbackPermit installing a release older than the local high-water mark.
--yesAnswer yes to interactive prompts.
--talkativePrint Sq [SECURITY] unveil and pledge diagnostics.

Przykłady

Adopt a host that already matches signed r543:

$ doas filees-install --adopt r543

Plan and apply the configured channel:

$ doas filees-install --dry-run
$ doas filees-install --apply

filees-rotate(8)

jawna zmiana generacji repozytorium FSFS

Rola

filees-rotate zastępuje aktywne (hot) repozytorium nową generacją. Nowa generacja ma nowy UUID i zaczyna się od rewizji 1 równej pełnemu zrzutowi starego HEAD, włącznie z wersjonowanymi właściwościami, takimi jak svn:needs-lock . Dziedziczy conf/ i hooks/ , jest weryfikowana przez svnadmin i porównanie drzew, po czym jest atomowo podmieniana. Stara generacja staje się zamrożonym, zablokowanym na commit archiwum FSFS. Istniejące kopie robocze nie przetrwają zmiany UUID.

Dla append-only profilu FileES rotacja jest narzędziem retencji, nie narzędziem wydajności. Nie ma wbudowanego harmonogramu. Uruchomienie filees-rotate jest decyzją operacyjną. Ten sam mechanizm stagingu i podmiany jest ponownie wykorzystywany przez LOAD_REPOSITORY_DUMP .

Wywołanie

filees-rotate -repo path -archive directory [-size threshold] [-age-days n] [-dry-run] [-force] [-break-locks] [-dump-depth n]

Flagi i czasowniki

Flaga / czasownikZnaczenie
-repo pathAbsolute path of the hot repository.
-archive directoryArchive directory on the same filesystem as the repository, so the swap is a rename.
-size thresholdRotate when packed size reaches this. Default 25GiB .
-age-days nRotate when revision 1 is older than n days. Default 365.
-dry-runPrint the decision without rotating.
-forceRotate regardless of triggers.
-break-locksProceed despite active locks. This destroys live edit passports.
-dump-depth nAlso archive a gzip dump of the last n revisions before HEAD. Zero, the default, writes no extra dump. The frozen FSFS archive is canonical.

Przykłady

$ filees-rotate -repo /STORAGE01/filees-repos/UUID \
    -archive /STORAGE01/filees-archive -dry-run
Usługa — startuje rc.d, to nie jest jednorazowy wpis z klawiatury

filees-public-authority(8)

autorytet udziałów publicznych i kody odbiorców

Rola

filees-public-authority to strona autorytatywna udziałów publicznych. Nasłuchuje na gnieździe uniksowym albo na loopback TCP. Nigdy nie kończy TLS. Pobiera liście przez svnlook i przekazuje je do filees-links(8) .

Nadzoruje filees-mail(8) public-loop jako wymagane dziecko. Sekret SMTP trzyma dziecko. filees-public-authority go nie ma. Przy SIGTERM albo SIGINT zamyka serwer HTTP, kończy dziecko i czeka, po czym kończy działanie — dzięki temu restart rcctl(8) nie może zostawić osieroconego pollera.

Epoki OTP odbiorcy, liczniki prób i skróty zaproszeń żyją pod korzeniem stanu udziałów publicznych. Cofnięcie i usunięcie odcinają dostęp natychmiast i porzucają oczekującą pocztę. Nie sprzątają jeszcze nieaktywnych plików epok; te pliki nie zawierają ani adresu skrzynki, ani kodu w postaci jawnej.

Wywołanie

filees-public-authority [-config path]

Flagi i czasowniki

Flaga / czasownikZnaczenie
[-config path]Ze SYNOPSIS.

Przykłady

Brak przykładu w mandoc; poniżej uczciwe wywołanie z opisu.

# typically /etc/rc.d/filees_public_authority
filees-public-authority --config /etc/filees/server.json

filees-links(8)

publiczna powierzchnia FastCGI udziałów, bez poświadczeń

Rola

filees-links serwuje pozbawiony poświadczeń publiczny HTML oraz pobrania plików/ZIP. Czyta filees-public-links(5) , nie filees.conf(5) . Posiada wyłącznie tymczasowy cache. O każdy liść pyta filees-public-authority(8) .

Proces nie używa JavaScriptu, nie ustawia ciasteczek i wysyła Cache-Control: no-store razem z haszowaną Content-Security-Policy. Nieznane, cofnięte i usunięte adresy dzielą jedno obrandowane HTTP 404, które nie odbija żądanej ścieżki.

Listing iteruje po zadeklarowanej mapie obiektów kanału. Nie przechodzi po drzewie repozytorium. Zobacz rozdział Udziały publiczne podręcznika HTML.

filees-mobile-v1(8)

wejście protokołu mobilnego (odczyt udziału, zapis pod mobile-uploads/)

Rola

filees-mobile-v1 to set-id'owe wejście dla _filees-mobile . Instalowany obraz ma właściciela _filees-state : _filees-access , tryb 4550 — tę samą klasę co filees-client-entry(8) .

Klient mobilny jest parowany z już aktywowanego pulpitu. Dziedziczy raz listę repozytoriów tego pulpitu. Telefon może odczytać przyznany udział i pisać wyłącznie pod mobile-uploads/ . Nowa ścieżka to unikalny dopisek. Ta sama ścieżka pod mobile-uploads/ z inną treścią staje się nową rewizją Subversion. UPLOAD_TREE wchłania oznaczony zip jako jeden commit; nieoznaczony zip jest odrzucany w całości. Projekcja mobilna nie dostaje editing_policy .

sshd(8) używa współdzielonego pliku authorized_keys . Linia command= przypisana do klucza wybiera ten obraz. Blok match dla _filees-mobile nie ma ForceCommand .

Wywołanie

filees-mobile-v1

Flagi i czasowniki

Brak flag — proces nie przyjmuje argumentów operatora.

Przykłady

Brak przykładu w mandoc; poniżej uczciwe wywołanie z opisu.

# authorized_keys command= for _filees-mobile
filees-mobile-v1
Wymuszone polecenie — odpala je sshd; flag nie wpisujesz

filees-recovery-entry(8)

wydawanie archiwów po usunięciu strefy, jedna operacja

Rola

filees-recovery-entry to set-id'owe wejście sesji dla _filees-recovery . Drugi obraz tej samej binarki jest instalowany jako /usr/local/libexec/filees/filees-recovery-authorize , właściciel root , grupa wheel , tryb 0555, ponieważ sshd(8) wymaga, żeby każdy komponent AuthorizedKeysCommand należał do roota. Wyszukiwanie klucza i usługa sesji są więc odrębnymi plikami wykonywalnymi.

Klient przedstawia klucz odtwarzania Ed25519 przypisany do jednej operacji, pochodzący z zestawu .fkr zapisanego podczas usuwania strefy. Helper autoryzujący emituje ograniczoną linię klucza związaną z tym jednym ID operacji i odmawia po upływie download_until . Protokół sesji to dokładnie dwa czasowniki:

list <operation_id>
get  <operation_id> <archive_id>

Wejście działa tylko do odczytu ( stdio rpath ) i nigdy nie widzi klucza prywatnego. Klucz nie daje dostępu SVN, powłoki ani żadnej innej operacji.

Wywołanie

filees-recovery-entry

Flagi i czasowniki

Brak flag — proces nie przyjmuje argumentów operatora.

Przykłady

Brak przykładu w mandoc; poniżej uczciwe wywołanie z opisu.

# session verbs after the .fkr key is accepted
list <operation_id>
get  <operation_id> <archive_id>

Styl

Źródła leżą w docs/man/man5, docs/man/man7 i docs/man/man8. Makra mdoc. Kanoniczny jest angielski. Sekcja 8 dla każdego polecenia serwera.

mandoc -T lint docs/man/man8/filees-admin.8
man -l docs/man/man7/filees.7

Instalacja

packaging/build-server.sh kopiuje strony do bundla jako share/man/manN/. install-server.sh instaluje je pod $PREFIX/man (domyślnie /usr/local/man).

man filees
man 5 filees.conf
man 8 filees-admin
