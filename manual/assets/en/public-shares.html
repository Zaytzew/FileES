Public shares

Share files with someone who will never install FileES. This is not a second way to write into your folders. Trust zones, the object map and the OTP protocol are in Tech Operations.

5.1 What this is

Verified live

A public share is a read-only landing page at the same HTTPS address as this manual. The visitor never receives write credentials. Upload Channel is a separate product — for receiving files from someone outside, not for distributing them — and does not share this process or these secrets with a public share.

The page uses no JavaScript, no cookies and no third-party resources. Branding is the filees:space system plus the owner logo and accent already stored on the server.

Why the public process never talks to Subversion itself is in Operations.

5.2 The share address

The public address is always:

https://<server-domain>/<realm-alias>/<slug>

Unknown, revoked and deleted addresses share one branded HTTP 404 that does not echo the path or the reason. The allowlist that also serves this manual is in Operations and in Operations.

5.3 Not a live mirror

VerifiedImplemented contract, not a defect.

A channel with no frozen revision follows HEAD, but not live: every new visit to the canonical address re-derives the file listing from the current SVN tree, so a file added later appears, a removed one disappears, and a rename shows under its new name. What is not live is an already-issued visit — a link carrying a ?v=… token freezes to whatever HEAD was at that visit, and does not catch up with later changes even to the same file. A channel with an explicit, positive revision freezes every visit to that one snapshot permanently, regardless of HEAD.

An empty folder is a legal placeholder. That is why the desktop copy says the share is not a live mirror of the folder — that describes a visit, not a channel following HEAD. The two clocks (object_map versus revision) are in Operations.

5.4 Open or closed

Open channel. Anyone with the address. You may set a shared password. After the password the visitor gets a twelve-hour signed link. The password screen shows your mark; it does not show the alias or the slug.

Closed channel. Each recipient gets their own invitation in the URL. The link alone is not enough. They ask for a code, receive an eight-digit OTP by mail, type it on the same page, then get a signed link that lasts until that code expires. Copying the signed link during that window carries the remaining access. After expiry the invitation URL returns to the gate. After revoke it is 404.

The public page never shows e-mail addresses. How hashes, epochs and visit tokens work is in Operations.

5.5 From the desktop

Udostępnienia publiczne appears only for the canonical owner, and only when the daemon advertises the complete list / create / update / revoke / delete set. Create and edit need an attached working copy.

  • Pick the working-copy root or any folder under it.
  • At most 4096 regular files. .svn and .filees are skipped. Symlinks are rejected.
  • Revoke stops delivery and keeps the record. Delete keeps an address tombstone.
  • A recipient list makes a closed channel. An empty list makes an open channel, optionally with a password. The password is never stored in the clear.
  • Empty revision follows the latest. A positive revision freezes that snapshot.

After opening the share, the visitor sees a collapsed-by-default details tree: name, type icon, size, download. They may take one file, one folder or the whole share as a bounded ZIP. This version has no thumbnails.

5.6 Turning it on

Public shares are installed disabled. After you have edited server.json and public-links.json, start authority before links, then reload httpd. The exact commands, health rule and man pages are in Operations.
