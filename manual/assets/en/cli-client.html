CLI client — user guide

filees-client for OpenBSD/amd64 and Linux/amd64 sends files to FileES on demand or from cron. It performs one operation and exits. You can publish a plain directory without an SVN working copy; neither the desktop application nor another daemon is required.

Program version: these steps require a CLI with install, update, autoconfig and publish. The older 0.1.0+r2016 package does not contain them. The base version 0.1.0 alone does not identify available commands; check filees-client version and filees-client help.

The shortest route is to install the program, use an existing activation, select a repository by name and choose the exact source folder. Later uploads need only filees-client publish invoices-2026. If your installation is already activated, skip step 2.

1. Install the CLI

You need the CLI archive for your platform and the svn, svnmucc and ssh programs. On OpenBSD, use the subversion package and system OpenSSH; on Linux, install Subversion and the OpenSSH client using your distribution's packages. The FileES installer does not install these dependencies.

Obtain a package through a trusted distribution. Before running the initial executable, verify the manifest signature with a known publisher key and check the archive size and SHA-256 against the manifest. Extract the verified archive and enter its directory. It contains bin/filees-client, a README and filees-client(1).

SystemSystem installation from the extracted package
OpenBSDdoas ./bin/filees-client install
Linuxsudo ./bin/filees-client install

The executable is installed as /usr/local/bin/filees-client. Installation without administrator privileges is also supported:

./bin/filees-client install --prefix "$HOME/.local"
export PATH="$HOME/.local/bin:$PATH"
filees-client version

The remaining examples assume filees-client is on PATH. For a per-user installation, retain this path in later sessions and use its absolute form in cron. Activate and publish as the user who will read the source and run the schedule.

2. Activate a new installation

If this CLI or desktop installation is already activated, continue with step 3. For a new installation, the server operator supplies the address, a known_hosts file containing the pinned host key and instructions for receiving an activation ticket. Replace filees.example.net and the email address below; office is the local server name.

Prepare a directory outside the publication source. Save the operator's file as ~/.local/share/filees/known_hosts:

install -d -m 700 "$HOME/.local/share/filees/servers"

Start activation:

filees-client activate-begin \
  --server-id office --server filees.example.net \
  --known-hosts "$HOME/.local/share/filees/known_hosts" \
  --state-root "$HOME/.local/share/filees/servers" \
  --email user@example.net

An accepted result means the request was accepted, not that activation has finished. Once you receive the one-time password, run the next command, type or paste the password on a separate line and press Enter. Do not put the password in command arguments.

filees-client activate-finish \
  --server-id office --server filees.example.net \
  --known-hosts "$HOME/.local/share/filees/known_hosts" \
  --state-root "$HOME/.local/share/filees/servers"

Success returns active. If the connection was interrupted after sending the password, resume with the retained identity and no second password:

filees-client activate-resume \
  --server-id office --server filees.example.net \
  --known-hosts "$HOME/.local/share/filees/known_hosts" \
  --state-root "$HOME/.local/share/filees/servers"

Finish and resume use the port saved when activation began. Older state without a saved port requires --remote-port PORT with the server-assigned value. Retain the activation directory and private key outside published files.

3. Select a repository and send files

List repositories from an existing activation:

filees-client autoconfig

Servers are discovered under $XDG_DATA_HOME/filees/servers or ~/.local/share/filees/servers. For another location, add --state-root /absolute/path/servers; select --server NAME (name or ID) when several servers exist. You may instead select an existing --profile /abs/client-profile.json or the older CLI's --activation /abs/servers/office. Use the same selection when saving your configuration.

A repository with write access must already exist on the server. Select its exact, unambiguous name. Autoconfiguration does not create repositories. This example saves a job called invoices-2026 and selects the year directory as its source:

filees-client autoconfig \
  --repo 'Invoices 2026' \
  --source /home/user/published/2026 \
  --name invoices-2026

Replace the path with your actual directory. If it contains 01/, 02/ and so on, those month folders appear directly in the repository. Selecting /home/user/published would also upload other years and its remaining subdirectories. The program adds no default filters and never widens the source to its parent.

Check the reported repository and canonical source. This step saves configuration but sends no files. Then run:

filees-client publish invoices-2026

Optional --message 'October invoices' sets the commit message, while --timeout 45m extends the operation time (30 minutes by default).

The program checks current access, compares files and reports progress on stderr. published=N reports uploaded files, while clean means there is nothing to send. All changed files form one atomic commit. The source remains free of .svn.

Publishing adds new files and updates changed files. It does not download remote changes, propagate local deletions or restore paths deleted on the server. skipped-deleted=N counts those skipped paths. publish accepts neither restoration nor reverse-reconciliation flags.

Where configuration lives

The job profile, lock and private journal live in $XDG_CONFIG_HOME/filees-cli/NAME or ~/.config/filees-cli/NAME. SVN, svnmucc and SSH are discovered during configuration, and their absolute paths are saved for cron. You can select them with --svn, --svnmucc and --ssh.

Repeating the same configuration is safe. Another source or repository requires another job name. Renaming the repository on the server retains its identity selection. For state outside the default location, use the same flag in both commands:

filees-client autoconfig --repo 'Invoices 2026' \
  --source /home/user/published/2026 --name invoices-2026 \
  --config-root /home/user/filees-jobs
filees-client publish invoices-2026 --config-root /home/user/filees-jobs

The state directory must be outside the source. An existing directory must already be private and writable by the user. Autoconfiguration reuses the existing activation key and port, without copying them or requesting another one-time password.

4. Run from cron

First complete a successful manual publication. You can then add this example to the same user's crontab. Adjust the times, absolute executable path and log path; keep the log outside the source.

0 9,15,20 * * * umask 077; /usr/local/bin/filees-client publish invoices-2026 --timeout 30m >> /home/user/filees-publish.log 2>&1

Include a custom --config-root in cron too. For a per-user installation, use /home/user/.local/bin/filees-client. Cron must use the same activation and job profile; switching to another user such as root does not move configuration. FileES commands do not install crontab entries automatically.

When another program produces the files, run FileES after its success. For example, with ksefpuck:

/usr/local/bin/ksefpuck && /usr/local/bin/filees-client publish invoices-2026 --message ksefpuck

Keep && so a failed producer stops the chain. The source should contain the producer's finished output. A lock refuses concurrent publication of the same job; an unchanged rerun creates no additional commit.

5. Update the program

Updates use a separate signed CLI channel and retain activation, job profiles and cron. Run with write access to the same prefix used for installation:

InstallationUpdate
OpenBSD, systemdoas /usr/local/bin/filees-client update
Linux, systemsudo /usr/local/bin/filees-client update
Per-user"$HOME/.local/bin/filees-client" update --prefix "$HOME/.local"

--check checks the available release without downloading its archive or replacing the executable, but still writes state and a lock inside the prefix. After an interrupted installation, repeat the same command; files are replaced separately with the executable last. Do not erase installer state to force an older release. A development build without the publisher key cannot install code from the network.

After installation, use man filees-client. In an extracted archive for either platform, use man -M ./share/man filees-client. The installer places the page under the prefix in man/man1 on OpenBSD and share/man/man1 on Linux.

Advanced: working copies and the older INI

The older checkout and sync commands still use an INI file. --wc selects one of its entries rather than a free-form path. This example uses OpenBSD tool paths; adjust the absolute paths on Linux. Replace the identity, host pin and URL with your existing activation's values. A no-WC URL must select the repository root.

[tools]
svn=/usr/local/bin/svn
svnmucc=/usr/local/bin/svnmucc
ssh=/usr/bin/ssh
log_dir=/home/user/filees-log
[realm]
identity=/home/user/.local/share/filees/servers/office/identity/id_ed25519
known_hosts=/home/user/.local/share/filees/known_hosts
host=filees.example.net
port=22
only=!invoices
[wc "invoices"]
path=/home/user/published/2026
url=svn+ssh://_filees-data@filees.example.net/REPO_UUID

Create log_dir beforehand as a private, writable directory outside the source. Its journal records time, stage and result and rotates after 5 MiB. Save the example INI outside the source, for example as /home/user/filees-client.conf.

OperationBehaviour
checkout, then syncCreates a WC, downloads changes and publishes additions, modifications and local deletions. Conflicts stop the commit.
sync -nwcPublishes a plain directory like publish, without downloading changes or propagating local deletions.
sync -nwc -restore-setExplicitly permits adding source files previously deleted in the repository.
sync -nwc -reverse-reconcile-setDownloads one revision and makes the local folder match it, including overwriting files and deleting local extras. Does not commit.
filees-client sync --config /home/user/filees-client.conf --wc invoices -nwc

For checkout, select a separate, new WC destination in the INI. Do not use it as a publish source. restore-set and reverse-reconcile-set require -nwc and are mutually exclusive; applying the reverse local tree is not atomic. Symbolic links and non-regular files inside a no-WC source are refused.

Repository import and large files

dump-load creates a new repository and WC from an SVN dump. It requires an existing client-profile.json, repository-creation permission and new target and private state directories:

filees-client dump-load --profile /abs/client-profile.json \
  --dump /abs/archive.dump --name 'Archive' \
  --target /home/user/archive-wc --state /home/user/import-001

The state and target parents must exist. After interruption, repeat exactly the same arguments and state; the saved request resumes the same import. Existing repositories and WCs are never overwritten.

Whale handles individual large files. whale-put uploads a file. Downloading starts with whale-get-quote, which reports the size and operation ID; only whale-get-confirm --id ID starts transfer. whale-status, whale-retry and whale-resume share the same profile and private state. See the command manual for complete arguments.

When an operation fails

SituationWhat to do
autoconfig or publish is missingCheck the version and executable path. Install a verified package containing those commands.
No activation found, or the choice is ambiguousUse the correct user, --state-root, --server, --profile or --activation.
The repository cannot be published toCheck the exact name and permissions with the operator. Publishing requires an active writable repository without mandatory edit locks.
No connection, revoked access or a rolled-back generationRestore connectivity or ask the operator to resolve the server state. The CLI does not fall back to an old access list.
The job is already runningWait for the previous run to finish. Do not remove the lock to allow a second upload.
The open-file hard limit is too lowAn administrator must increase the limit for the user or service. The CLI adjusts the soft limit itself; an oversized set is refused before commit without silently splitting it.
The connection was interrupted during commitThe CLI checks whether the files reached the server. After a reported error, restore connectivity and rerun the same job; unchanged files create no new commit.
A normal WC has conflictsResolve them in SVN before another sync. The CLI does not resolve conflicts automatically.

With Whale, a file may already be on disk while the operation awaits confirmation that the server released its cache and space reservation. Inspect whale-status --id ID; use whale-retry --id ID after a failure or whale-resume --id ID after process interruption, keeping the same profile and state.

Exit code 0 means success; a nonzero result stops an && chain. Operation errors usually return 1, and invalid argument syntax returns 2. Keep activation state, job configuration and the private journal outside published folders.
