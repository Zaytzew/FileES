Chapter 5: Public Shares

5.1 Trust model

Verified liveCanonical HTTPS endpoint, FastCGI links, Unix backchannel and authority isolation accepted on OpenBSD.

Public Shares is a distribution channel, not a second write path. Upload Channel is a separate vertical and must not share this process or these credentials.

Three processes, three owners:

ProcessOwnerMay seeMust not see
filees-links_filees-linkspublic request, visit token, private cacheSVN credentials, SMTP secret, recipient addresses
filees-public-authority_filees-statechannel records, svnlook, OTP hashesSMTP password (held by the mail child only)

TLS belongs to relayd/httpd. FileES never embeds a TLS stack. The public HTML uses no JavaScript, no cookies and no third-party resources. Branding is the filees:space system plus the owner accent colour and logo already stored on the server.

Design rationale / push from authority, never pull from the public zone
Decision
The public process asks for (channel, public_id, revision); authority resolves the map and pushes the leaf.
Why
The public zone stays credential-free and the expensive svnlook stays on the state account.
Rejected
Materialising a published tree; giving links a service-repository working copy; embedding TLS.
Cost
A backchannel and a private cache are mandatory for usable large binaries.

5.2 Canonical URL

The public address is always:

https://<server-domain>/<realm-alias>/<slug>

Static document-root paths are an explicit allowlist: /, /index.html, /favicon.ico, /robots.txt, /.well-known/acme-challenge/* and /assets/*. The HTML manual lives in that last prefix. Everything else is a virtual FileES location. Adding a realm must not create a directory and must not reload httpd. Publishing a new manual page is only a new file under /assets/. See the publishing graph.

Unknown, revoked and deleted addresses share one branded HTTP 404 that does not echo the path, alias, slug or reason. robots.txt is static Disallow: /.

5.3 Object map versus revision

VerifiedDocumented after the 2026-08-14 live observation; this is the implemented contract, not a defect.

Two clocks exist:

  • Revision is chosen at each visit. If the channel has no do-not-follow, authority reads HEAD and freezes that revision for the visit. Mapped file contents therefore follow HEAD.
  • Composition is the object_map written at CREATE or UPDATE. Listing and download iterate only that map. A file added to the folder later is invisible; a removed file stays listed; a rename keeps the old name.

An empty selected folder is a legal placeholder. Later files require an explicit channel update. That is why the desktop copy says the share is not a live mirror of the folder.

Changing composition to a derived tree walk would require deterministic public_id values (for example HMAC of path and a channel secret) so mailed links survive a new file. That decision has not been taken. Until then the concept's “refreshes by itself” sentence applies only to the content of already mapped leaves.

5.4 Open, password and recipient OTP

Open channel. Optional Argon2id password. A successful gate issues a twelve-hour signed visit URL. Password verification is globally serialised to one in-flight Argon2. The password screen shows the FileES mark, the owner logo and the owner accent; it does not show alias, slug or explanatory text.

Closed channel. Each recipient gets an invitation identifier in the URL (?invite=; legacy ?token= is accepted as an alias). The identifier is not a bearer. The landing page is a gate: the recipient asks for a code, authority mails an eight-digit OTP with a five-minute epoch, five attempts and a resend cooldown. Resend in an active epoch does not rotate the code or extend the TTL. After a correct OTP the public process receives only the invitation hash, the epoch UUID and an absolute expiry, then issues a signed URL that is a bearer exactly until that expiry. Copying the URL transfers the remaining window. After expiry the same invitation URL returns to the gate. After revoke it is 404.

The public projection never contains e-mail addresses. Plaintext passwords and OTP codes are hashed before they cross IPC or SVN-backed control state.

5.5 Desktop owner path

Only the canonical owner sees Udostępnienia publiczne, and only when the daemon advertises the complete list/create/update/revoke/delete set. Create and edit require an attached working copy. The GUI maps at most 4096 regular files, skips .svn and .filees, rejects symlinks and keeps a stable public_id for paths that remain. Revoke stops delivery and keeps the record. Delete keeps an address tombstone.

After admission the listing is a collapsed-by-default details tree: name, type icon, size, single-file download. Selection, folder and whole-share ZIP are bounded; every leaf is authorised and materialised in the private cache before archive output starts. There are no thumbnails in this version.

5.6 Server operations

Public Shares are installed disabled. After editing server.json and public-links.json:

# merge openbsd/public-links.httpd.conf into the origin server block
doas rcctl enable filees_public_authority filees_links
doas rcctl start filees_public_authority
doas rcctl start filees_links
doas rcctl check filees_public_authority filees_links
doas httpd -n && doas rcctl reload httpd

Start authority before links. Authority is unhealthy if its mail child dies; a stop signal closes HTTP, terminates the child and waits, so rcctl restart must not leave an orphan poller. See filees-public-authority(8) and filees-links(8).
