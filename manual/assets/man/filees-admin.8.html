NAME

filees-admin — FileES administrative tickets, revocation, repository repair and erasure closure

SYNOPSIS

filees-admin [-config path] ticket create mailbox [--ttl duration] [--join-realm-alias alias]

filees-admin [-config path] ticket resend --ticket-id uuid

filees-admin [-config path] ticket revoke --ticket-id uuid

filees-admin [-config path] ticket list

filees-admin [-config path] operation inspect --operation-id uuid

filees-admin [-config path] client revoke --client-id uuid [--reason text]

filees-admin [-config path] client revoke-realm --realm-id uuid [--reason text]

filees-admin [-config path] repo transfer-owner --repo-id uuid --realm-id uuid

filees-admin [-config path] repo check-state [--realm-id uuid]

filees-admin [-config path] repo prune [--realm-id uuid] [--older-than duration] [--apply]

filees-admin [-config path] repo activate --repo-id uuid --realm-id uuid

filees-admin [-config path] repo rotate --repo-id uuid [--size size] [--age-days days] [--force] [--dry-run]

filees-admin [-config path] repo lock-guards --repo-id uuid --owner-realm-id uuid [--apply]

filees-admin [-config path] repo reap-passports --repo-id uuid --owner-realm-id uuid [--path relative]

filees-admin [-config path] share list [--json]

filees-admin [-config path] share delete --channel-id uuid

filees-admin [-config path] erasure complete --operation-id uuid [--partially-retained]

filees-admin version [--install-config path]

DESCRIPTION

filees-admin is the operator command for onboarding tickets and a small set of fail-closed administrative actions. It writes structured JSON to standard output and diagnostics to standard error. It must run with effective user _filees-state. Creating a ticket as root produces a root-owned mode 0600 file that the set-id onboarding entry intentionally cannot read.

version reports the binary build version (including its SVN revision) and platform. Aliases are --version and -version. No service identity transition or server configuration is required, so the binary can be identified even when server.json is suspect. It also reports update_channel from /etc/filees/install.conf and recorded_release from the installer's state directory. Use --install-config after the version command to select a nonstandard installer configuration. Unavailable metadata is reported as unknown without hiding the build version. The update channel is a local subscription setting, not a label baked into the binary; promoting an unchanged release does not require rebuilding it. The recorded release does not prove that resident services have restarted.

Normal repository create, grants, public shares and realm removal are desktop control-plane operations. The repo check-state and repo prune verbs are exceptional operator recovery tools for abandoned repository creation state, not an alternate repository-management interface.

COMMANDS

ticket create
Issue a one-time invitation to mailbox and send it immediately. The mailbox must come before any flag. Without --join-realm-alias the ticket authorises a new realm. With the flag the server resolves the immutable alias now and stores the approved realm ID; the client never submits that ID. The invitation capability is not printed.
ticket resend
Replace a failed delivery capability without changing recipient or TTL.
ticket revoke
Delete an unused ticket. A claimed ticket has already been replaced by an operation bundle.
ticket list
List remaining tickets. Names are sha256(mailbox) so the file name does not reveal the address.
operation inspect
Show one onboarding operation.
client revoke
Write a durable revoking record, drop generated SSH/SVN access, then commit the revoked client. An identical retry is idempotent; a different reason is rejected.
client revoke-realm
Revoke every installation of a realm with the same sequence.
repo transfer-owner
Change owner_realm_id and regenerate data-authz. Existing grants issued by the previous owner are not touched.
repo check-state
Read repository-creation backend records and correlate them with canonical authority, FSFS/staging presence and, for a possible abandoned initial creation, svnlook(1) youngest revision. Normal active repositories are omitted. The optional --realm-id limits the JSON report to one realm. This command does not remove repositories.
repo prune
Report the same abandoned-creation candidates as repo check-state. Without --apply it is a dry run and changes nothing. --older-than defaults to 1h and prevents a recent creation attempt from being selected. With --apply, only records marked prunable and old enough are removed. For a published candidate the canonical state must be initializing, there must be no staging tree, and FSFS must be absent or exactly r0. Before removal the command durably records prune_pending, blocks commits and checks the youngest revision again. An active repository, an initializing repository at r1 or later, and an ordinary deletion tombstone are never removed by this path.
repo activate
Repair a repository whose CREATE_REPOSITORY succeeded and whose initial import reached the backend, but whose INITIAL_COMMIT control ticket never landed, so the canonical record stayed initializing. Clients keep projecting such a repository as not yet ready and refuse to attach, while the FSFS repository is usable and may already carry commits. Requires --repo-id and --realm-id. Resuming from the client is possible only while its local provisioning operation survives; once that file is gone this command is the only way out.
repo rotate
Perform an FSFS generation change on one repository, with the same per-command sandbox profile every other administrative operation gets, and with paths taken from the server configuration rather than from argv. Requires --repo-id. Rotation happens when the packed repository reaches --size (default 25GiB) or its oldest revision is older than --age-days (default 365); --force rotates regardless of both triggers and --dry-run evaluates them and prints the decision without rotating. The standalone filees-rotate(8) takes its paths from the command line and applies no sandbox; prefer this command.
repo lock-guards
Report, and with --apply install, the repository hooks that guard locking. Existing hooks are never overwritten. Requires --repo-id and --owner-realm-id.
repo reap-passports
Remove expired passports from one repository. Requires --repo-id and --owner-realm-id; --path addresses a single legacy expired passport by its relative path.
share list
List Public Shares channels. --json emits the listing as JSON instead of a table.
share delete
Delete one Public Shares channel, addressed by --channel-id as printed by share list.
erasure complete
Close a data-erasure request after the operator has verified backup retention. --partially-retained records that policy still requires some copies.

EXAMPLES

Create a new-realm invitation:

$ doas -u _filees-state filees-admin ticket create user@example.com

Authorise another desktop in an existing realm:

$ doas -u _filees-state filees-admin ticket create user@example.com \
    --join-realm-alias acme --ttl 24h

Inspect and then remove abandoned empty initial creations for one realm:

$ doas -u _filees-state filees-admin repo check-state --realm-id UUID
$ doas -u _filees-state filees-admin repo prune --realm-id UUID \
    --older-than 1h
$ doas -u _filees-state filees-admin repo prune --realm-id UUID \
    --older-than 1h --apply

MOBILE RECOVERY

Run mobile recover --request-id UUID as the owner of the mobile ledger directory, normally ‘doas -u _filees-state filees-admin’. The command locks the operation and searches repository history to restore an existing receipt without replaying the upload. An unresolved legacy operation remains blocked by default.

Only after disabling new mobile sessions and stopping all prior workers and SVN children may the administrator add --allow-retry --confirm-workers-stopped --reason TEXT. This is an explicit operator attestation of maintenance quiescence, not a process scan. A free lock is not sufficient for pre-upgrade children. The command writes a private durable before-image/planned-decision audit before replacing the ledger record. It preserves the request ID. The optional --ledger PATH selects a private ledger owned by the effective user. Do not edit or remove pending records manually.
