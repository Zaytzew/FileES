FileES / canonical system manual

Architecture, operation and recovery

A file-centric synchronisation system built around explicit ownership, durable artifacts, bounded publication and recoverable failure. This edition is a multi-page HTML manual. Server operators also have OpenBSD mandoc pages under docs/man/.

How to read this manual

The previous single-file manual-filees.html is now a compatibility stub. The living document is this directory. Each page keeps the filees:space visual system and has no network dependencies.

FileES is a work-in-progress. On-disk formats, protocols and schemas still change. Do not treat a maturity badge as a product release.

Operator entry points

A desktop user starts at the user guide. An OpenBSD operator starts at server installation and then at the mandoc pages that ship with the server bundle:

man filees
man filees.conf
man filees-admin
man filees-install

Those pages follow the same contract as the rest of the FileES server: filesystem first, no resident FileES daemon, system sshd as the only privileged endpoint.

Publishing this set on manual.filees.space

Public Shares and the HTML manual share one HTTPS origin. httpd does not know realms or slugs. It only owns a small static allowlist; everything else is FastCGI. A chapter file left next to index.html as /architecture.html would therefore be treated as a virtual FileES path and return the branded 404.

This directory is the document-root image. It lives in Subversion as ^/manual. On the host, /var/www/htdocs is a working copy of that subtree. svn update is the publish step. Do not add a new location and do not reload httpd.
