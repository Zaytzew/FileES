NAME

filees.conf — FileES server toolchain configuration (/etc/filees/server.json)

DESCRIPTION

The FileES server tools read a single JSON document, by default /etc/filees/server.json. The schema name is filees.server-toolchain/v2. The file must be a regular file, not group- or other-writable, and every path value must be absolute.

Loaders that need secrets take an explicit secret set. A tool that does not need SMTP does not open the SMTP password file.

KEYS

schema
Must be filees.server-toolchain/v2.
display_name
Required human-facing server name, at most 80 Unicode characters. Changing it does not change immutable invitation.server_id. Run filees-operation(8) recover to publish the new name to all active client projections.
root
Private onboarding directory. Default layout is /var/filees/onboarding.
otp_pepper_file
At least 32 bytes of base64 pepper. Regenerating it invalidates outstanding OTPs.
worker_private_key_file, worker_public_key_file
Ed25519 key used by filees-worker(8) when it pins the client helper.
activation
Absolute runtime paths: activation root, session root, authorized_keys, service authz, service working copy, service repository, client and mobile entry paths, and the svn and svnserve binaries.
repositories.root
Absolute FSFS storage root. /var/filees/repositories is a default, not a required mount point.
repositories.results_root
Durable worker results, separate from FSFS data.
repositories.url_prefix
Canonical public prefix. It must be svn+ssh://_filees-data@host/ with no explicit port. The SSH port belongs in the client transport profile and in invitation.server_address.
repositories.deletion_retention_days
Days to keep a verified dump after a permanent detach. Omitted defaults to 30. Explicit 0 deletes FSFS immediately and writes no dump.
repositories.recovery_admin_contact
Mailbox used for data-erasure notices.
repositories.data_erasure_max_days
Days an operator has to confirm backup-retention closure of a data-erasure request before it is treated as overdue. Omitted defaults to 90. A value outside 1-3650 is rejected.
repositories.whale_root
Absolute root for Whale transport operational payloads (spool, journal), kept separate from the small repository-control journal under repositories.results_root. Optional; a non-absolute value is rejected. Omitted defaults to results_root/whale.
public_shares
Optional distribution channel. Disabled by default. See filees-public-authority(8) and filees-public-links(5).
public_shares.authority_staging_root
Absolute private staging directory, independently configurable from the frontend cache. Omitted defaults to /var/filees-downloads/authority. Use mode 0700, owned by _filees-state, on persistent storage with sufficient capacity. Exclude it from backups and external cleanup. Changing the path requires restarting filees_public_authority to establish a new OpenBSD unveil profile.
public_shares.max_size
Maximum leaf size in bytes, default 1 GiB. At most two authority fetches run concurrently; reserve staging capacity accordingly.
public_shares.max_channels_per_realm
Upper bound on live channels one realm may hold. Omitted defaults to 128.
public_shares.password_required
Refuse to publish a channel that carries no recipient password. Off by default.
public_shares.frost_key_file
Private key from which public_id is derived. It is read as a secret: absolute path, regular file, not group- or other-writable. Replacing it changes every future public address; existing ones keep working.
operator_branding
Optional presentation of this server in public HTML. leading_color is the accent colour and logo_file an absolute path to the operator logo. Both are cosmetic: nothing in authorisation, addressing or transport reads them.
upload
Optional closed upload-shelf intake. intake_root must be absolute and shared with filees-public-links(5). The OpenBSD layout is /var/filees-downloads/intake, owned _filees-links: _filees-public mode 0770. trash_root holds AV rejects in a private directory (0700), owned by _filees-state. max_trash_size limits their total logical payload bytes, including hidden entries and incomplete copies; zero or omission disables this limit. The example uses 10737418240 bytes (10 GiB). Metadata and filesystem allocation overhead are not included. When full, the worker retains the incoming job and reports an error; it does not shorten the 48-hour retention to make room. Configure the separate intake budget in filees-public-links(5) as well. av_command is required once intake is configured and runs as _filees-state from filees-worker(8) upload-reap.
invitation
Stable server_id, public SSH server_address and the verified Ed25519 known_host line carried in every invitation.
smtp
Submission-style relay. tls is starttls, implicit or none (loopback only). password_file is required when username is set.
operation_ttl, otp_attempts
Onboarding operation lifetime and wrong-OTP limit.
reverse_port_first, reverse_port_last
Permitted reverse-tunnel ports. A single static port is the supported deployment.

FILES

/etc/filees/server.json
Installed configuration.
/etc/filees/server.example.json
Example shipped in the server bundle.
/etc/filees/otp.pepper
OTP pepper, mode 0600.
/etc/filees/smtp.password
Optional SMTP secret, mode 0600, owner _filees-state.

EXAMPLES

Validate the non-secret path after editing:

$ doas -u _filees-state filees-admin ticket list
